# Model Switcher design contract

## 1. Atmosphere & Identity
Operational, legible, calm. This is a Hermes Dashboard configuration workspace, not a marketing page. The matrix is the primary workspace, the change rail is secondary. Signature: an explicit selection summary connecting exact profile/slot targets to reviewed changes. Preserve host theme and runtime protections.

The page introduction states the practical benefit in one sentence. Task headings lead with actions: Select your targets, Choose your routing, Preview, Apply. Presets remain a compact reusable-setup strip. The refresh/recovery toolbar separates orientation from editing. Selection counts announce changes politely; model search explains zero matches and how to recover.

## 2. Color
Use host semantic tokens, not a new brand palette: surface --background, text --midground, muted --text-muted-color, border --color-border, focus --color-ring, accent --accent-color. Preserve legacy aliases. Fallbacks: surface #16181d, text #e6e8ee, muted #9aa1ad, border #3a3f48, accent/focus #6f9bff, danger #e5534b, success #3fb950, warning #d29922. Accent is restricted to primary actions, focus and selection, not background floods. Text-backed semantic states; never color alone. Verify AA contrast for actual light/dark host token pairs. Sticky surfaces must resolve opaque colors and refresh with theme changes.

## 3. Typography
Inherit the host sans-serif stack. Technical paths use ui-monospace, SFMono-Regular, Consolas, monospace. Body 14px minimum, secondary text 13px minimum, section titles 16px, page title 22px. Body line-height 1.5. Use weight 400/500/600 and tabular figures for counts. Human-readable labels lead; exact identifiers remain accessible in details. No remote fonts.

## 4. Spacing & Layout
4px base; 4/8/12/16/24 spacing scale. Controls 38px minimum with generous checkbox labels. Wide view: matrix and bounded editor rail (~360px) in one workspace; editor remains before matrix in DOM for action discoverability. Below ~1100px stack a compact editor and matrix; advanced fields use disclosures. At 768/375px controls wrap or stack, profile options are bounded/searchable, no document horizontal overflow. Table owns horizontal scroll and sticky header/profile identity. Exact configured/observed route IDs never wrap mid-token: keep them on one line with 240px minimum route cells. A displayed route reads `provider · model` (U+00B7 with single spaces) with the model id verbatim — never `provider/model`, which doubles a vendor namespace (`openrouter/openrouter/pareto-code`, `primalabs/primalabs-ai/…`) because Hermes model ids usually carry their own prefix. The typed chain and exact-removal inputs keep the `provider/model` syntax they parse. Protect Slot/Family/State widths (160/176/112px) too, so ordinary labels do not fragment when routes grow. Keep the native horizontal scrollbar and a plain scrolling instruction discoverable; no decorative shadow/fade. Do not freeze so many columns that narrow viewports lose route content.

## 5. Components
Profile filter: clearly named 'Profiles shown', show-all reset independent from editing targets. Matrix: select-all matching writable rows, clear selection, selected-profile/slot count and explicit hidden-selection count; read-only reasons visible. Filters use persistent labels and human-readable family/task names; reset affordance and result count. Editor: Choose a model / Set fallback sequence / Reset to default or inherited routing / Turn off fallback; inline explanation and applicability, no silent target exclusion. Exact-model removal is a separate advanced action. Picker retains exact provider ids and manual entry. The picker keeps 62-model aggregators usable without leaving native controls: a provider whose ids span two or more labs gets a labelled `Lab` select (All labs with the provider count, then each lab by label and count) and a `Filter models` search box above `Model`; rows carry the leaf id under one `<optgroup>` per lab, while the option value, option title and Route line keep the full id. A filtered-out selection stays pinned at the top of the select, never silently dropped. Unknown prices are stated once under the select for a wholly unknown provider instead of on every row; a real rate, `free` and `included in subscription` stay per row. Preview shows actual before/after and profile/slot refusal identities. Apply gates remain unchanged and explain disabled states. Drawer has summary, close/Escape, focus entry/trap/return. All controls cover hover, focus-visible, active, disabled, loading, empty and error states.

Host data notice: one non-blocking, polite status line for loading, partial or unavailable host evidence. Use muted text while loading and warning text for missing evidence; config-only controls remain usable. Apply progress is a compact ordered list beside Apply: pending, awaiting host, confirm, done, failed and recovery required are written as text. Refusals use danger text with an explicit status kind, never inferred severity.

Host confirmation: neutral “Hermes asks you to confirm this model” dialog inside the plugin root, host --background/--midground pair, --color-border, 6px radius, 16px padding, maximum 520px width with 16px viewport gutters. The backdrop uses the host --foreground overlay (transparent fallback); no new shadow or palette. Confirm and Cancel use existing button primitives. Only one modal owns keyboard focus; Tab cycles, Escape cancels, text wraps and the dialog scrolls vertically. Apply is focusable with aria-disabled while unavailable so modal focus can return without reviving a consumed review. Catalog payloads without timestamps are labelled “from Hermes picker cache”, never treated as fresh or warned stale simply for lacking timestamps. Explicit refresh is labelled as requested, not proof of a fetch time. Catalog structure is data-driven, not decorative: providers whose `authenticated` is false never interleave with working ones — they sit in one collapsed native disclosure at the bottom, and the header states set-up versus total providers and models. Filters are labelled native selects and `aria-pressed` toggles over the loaded catalog (lab with counts, set-up provider, setup status, in-use slots, capability fields when present, and an `id:free` suffix toggle that is never a price claim); narrowing hides empty groups and a narrowed group header states rows shown of models published (`4 of 67 models`), never the untouched catalog total; every filter whose control disappears with a catalog-profile switch is cleared, so a select never reads "All labs" while a stale filter applies. Price controls and price sorts exist only when at least one model is priced or free; otherwise one note explains their absence and sort falls back to Name. Grouping is an explicit Provider / Lab / None select — Lab groups span providers and show the leaf id with the full id in the title, None adds Provider and Lab columns and keeps the 100-row page — and the catalog profile is a visible select whose scope the provenance line repeats. That profile also scopes the picker, its model list and the catalog's `Use` gate, so the editor names the case where the write targets live in other profiles.

## 6. Motion & Interaction
No decorative motion or smooth-scroll dependency. Optional color transitions <=120ms; disable under prefers-reduced-motion. Preserve selection when filters narrow; display selected targets outside filters and explicitly identify them in preview. Bulk select includes matching writable slots only. Selection/editor changes invalidate review. Filters do not silently add targets. Real requests remain authenticated through the host SDK.

## 7. Depth & Surface
Flat surfaces with 1px borders, 6px radius baseline. No gradients, glass, decorative shadows or dashboard card grid. Use spacing and weight for hierarchy.

Refinement floor: 16px plugin-root gutters; 8px form rhythm; two-column narrow matrix filters; 14px matrix body and at least 13px secondary/badge/catalog text. Disclosures are native controls, not nested cards. Provider notices use neutral 1px separators and explicit text, not thick side stripes. Catalog counts remain a flat definition list. Never trade pinned editor/target/action order or the first Tab target for density.

Inline table/editor borders resolve modern host tokens before legacy aliases, just like control chrome. Host danger/success/warning tokens remain authoritative. A modern host supplying only foreground/surface may derive semantic text from the established fallback and `--midground`; absence of that token preserves legacy colors. Measure actual enabled text in both prescribed host themes. Unavailable `aria-disabled` actions keep existing focus behavior but do not acquire enabled hover/pressed emphasis.

## 8. Accessibility Constraints & Accepted Debt
Keyboard-reachable native controls, associated labels and inline descriptions, visible focus, indeterminate bulk checkbox, text status indicators and aria-live action feedback. Dialog drawer manages focus and Escape. Responsive/keyboard/light-dark checks at 1440/768/375px required; no accessibility or performance pass implied by this contract. Runtime coverage is bounded by installed Hermes support; unsupported selectors stay read-only. Preserve preview/apply/readback/undo, stale reviews, exact identities, non-model settings and cost acknowledgment. No live route writes during visual verification; isolate mutation tests.
